## 1. 목적과 범위

**전체 목표**: 중학교 과학 수업에서 학생들이 스마트폰으로 하는 세로형 등반 게임. 메이플스토리 '인내의 숲' 분위기.
좌우 버튼만으로 거대한 나무 속을 600층까지 오르고, 20층마다 과학 퀴즈(총 30문제), 구글시트 랭킹.

**전체 단계**: 1차 이동 프로토타입(60층) → 2차 장애물 → 3차 퀴즈 → 4차 600층 확장 → 5차 구글시트·입장 화면·랭킹 → 6차 모바일 최적화·깃허브 페이지 배포.

**이번(1차) 범위**: 60층짜리 하나의 수직 맵. 좌우 이동, 계단 자동 오르기, 실제 물리 추락과 아래 발판 재착지, 부드러운 카메라, 완주 화면.
장애물·퀴즈·구글시트·입장 화면은 만들지 않는다.

**성공 기준**
1. 폰에서 직접 해봤을 때 조작이 재미있다 (사용자 판단).
2. 검증 봇이 실제 물리 그대로 60층을 완주한다.
3. 어디에 떨어져도 정상까지 다시 올라갈 수 있다.
4. 60Hz·120Hz 기기에서 같은 손맛이다.

## 3. 화면과 입력

- **레이아웃**: 세로 화면 전체. 위에 HUD(현재 층·최고 층·타이머, 게임 위에 겹침), 가운데 게임 캔버스, 아래 버튼 패널(화면 높이의 약 20%, 최소 96px, 아이폰 하단 안전 영역 반영). PC에서는 9:16 상자로 가운데 정렬.
- **월드 폭** 192 논리 픽셀(12칸 × 16px, 양 끝 1칸은 벽)이 항상 다 보임 → 가로 카메라 이동 없음.
- **픽셀 배율**: 정수 배율 = floor(캔버스 실제 픽셀 폭 ÷ 192). 남는 좌우 여백은 나무껍질로 채움. 보이는 높이 = 캔버스 높이 ÷ 배율.
- **터치**: 버튼 패널 위 모든 손가락을 Pointer Events로 추적. 손가락이 패널 왼쪽 절반이면 ◀, 오른쪽 절반이면 ▶. 손가락을 미끄러뜨려 옮겨도 인식. 여러 손가락이면 가장 최근에 누르거나 옮긴 쪽이 이김.
- **키보드**: ←/→, A/D. 동시에 누르면 나중에 누른 키가 이김.
- **브라우저 방해 차단**: 확대, 스크롤, 길게 눌러 메뉴, 텍스트 선택 (touch-action, user-select, contextmenu, viewport 설정).
- **타이머**: 첫 입력부터 시작. 고정 시뮬레이션 시간으로 계산(프레임 끊김 무관). 탭이 가려지면 일시정지. 정상 도착 시 정지. 표시 `mm:ss.cc`.

## 4. 이동과 물리

**좌표**: 논리 픽셀. y는 위쪽이 +(높이). 바닥 윗면 y=0이 1층. **층 = floor(발 높이 ÷ 16) + 1**.
**캐릭터 충돌 상자**: 폭 8 × 높이 22 (그림은 16×24, 발 중앙 정렬).
**고정 시간 간격**: 1/120초. 화면은 직전·현재 상태를 보간해서 그림.

**두 종류의 지형**
- **발판**(나무판·돌벽돌·가지, 두께 6px): 메이플 발판처럼 **위에서만 밟힘**. 떨어지다 윗면에 닿으면 착지, 아래·옆으로는 통과.
- **고체**(벽, 바위, 바닥): 사방이 막힘. 옆에서 부딪히면 멈춤.

| 설정 (`config.physics`) | 기본값 | 의미 |
|---|---|---|
| walkSpeed | 72 px/s | 최고 걷기 속도 (초당 4.5칸) |
| groundAccel | 900 px/s² | 출발 가속 (0.08초에 최고 속도) |
| groundDecel | 1200 px/s² | 손 떼면 감속 (미끄러짐 약 2px) |
| turnAccel | 1800 px/s² | 반대 방향을 누를 때 |
| airAccel | 270 px/s² | 공중 조작 (땅의 30%) |
| airDrag | 0 px/s² | 공중에서 손 뗐을 때 감속 (0 = 관성 유지) |
| gravity | 1100 px/s² | 중력 |
| maxFallSpeed | 420 px/s | 최대 낙하 속도 (초당 약 26층) |
| stepHeight | 17 px | 이 높이 이하 턱은 자동으로 오름 (1칸=16) |
| airStepTolerance | 3 px | 떨어지며 모서리에 아슬아슬하게 닿을 때만 올려줌 |
| fallCountFloors | 3 | 이 층수 이상 떨어지면 추락 1회 |

**한 스텝 처리 순서**
1. 입력 방향 d(−1/0/+1)로 가로 속도 갱신. 땅: 같은 방향 groundAccel, 반대 방향 turnAccel, 입력 없음 groundDecel. 공중: airAccel, 입력 없음 airDrag. |vx| ≤ walkSpeed.
2. 공중이면 중력 적용, 낙하 속도 상한.
3. **가로 이동과 자동 계단**: 땅에 있고 움직이는 중이면, 진행 방향 쪽 가장자리(오른쪽으로 갈 땐 발판 왼쪽 끝, 왼쪽으로 갈 땐 오른쪽 끝)가 새 위치의 몸 폭 안에 들어온 발판·고체 중 윗면이 발보다 0 초과 stepHeight 이하로 높은 것이 있으면 → 발을 그 윗면으로 올림. 공중에서는 airStepTolerance 이하일 때만.
   그 외에 고체와 겹치면 옆면에 붙이고 vx=0 (벽).
4. **세로 이동**: 내려가다 발판·고체 윗면을 지나치면(몸이 가로로 1px이라도 걸치면) 착지, vy=0. 한 스텝 최대 3.5px < 발판 두께 6px → 뚫고 지나가지 않음. 위로 움직이다 고체 아랫면에 닿으면 vy=0.
5. **땅 확인**: 몸 아래 발판이 하나도 안 걸치면 공중 상태로 전환(vy=0부터 낙하). → 가장자리에 최대 7px까지 걸쳐 설 수 있음.

**이벤트**: stepUp, leaveGround, land(떨어진 층수), bump(벽).
**추락 판정**: 공중에 뜬 순간 층 − 착지 층 ≥ 3 → 추락 횟수 +1, "−N층!" 표시, 10층 이상이면 화면 살짝 흔들림.
**계단 연출**: 물리는 즉시 16px 올리고, 그림은 0.07초 동안 톡 뛰어오르듯 따라감.
**알려진 연출 한계**: 꺾임에서 착지판에 막 올라선 순간 머리가 다음 계단과 잠깐 겹쳐 보일 수 있음 (캐릭터를 발판 앞에 그림, 메이플과 같은 방식).

## 5. 맵 구조

### 격자
- 셀 16×16. 열 0과 11은 벽(고체), 열 1~10이 안쪽.
- 행 r 발판은 그 셀 윗부분 두께 6px, **윗면 높이 = r×16**. 행 0은 바닥(고체).
- 바위 범퍼 = 1열×2행 고체. 넘을 수 없는 벽 역할.

### 계단 규칙
- **디딤판(tread)** = 한 행의 연속된 발판 구간 [c0..c1]. 경로 = 디딤판의 연속. 다음 디딤판은 진행 방향 바로 옆, 한 행 위. 한 행에 경로 디딤판은 하나.
- **비행(flight)** = 같은 방향 디딤판 묶음. 최소 2개. 마지막 디딤판이 **착지판**(꺾이는 곳).
- **꺾임**: 새 비행의 첫 디딤판은 착지판의 안쪽 옆, 한 행 위 (아래 비행의 디딤판 위로 두 행 간격).
- **머리 공간 규칙**: 서 있을 수 있는 윗면(발판·바위 윗면) 바로 위 한 행, 같은 열에 발판·바위가 있으면 안 됨. 예외: 바닥(행 0) 위 첫 디딤판, 바위가 얹힌 받침 발판(그 자리는 바위가 덮어 서 있을 수 없음). 캐릭터 22px ≤ 2×16 − 6 = 26px 이므로 두 행 간격이면 머리가 닿지 않음.

### 꺾임 종류
- **안전한 꺾임**: 착지판을 벽까지 늘리거나, 착지판을 한 칸 늘리고 그 위에 바위 범퍼. 지나칠 수 없음.
- **열린 꺾임**: 착지판 바깥에 빈 열이 1칸 이상 → 지나치면 떨어짐.

### 추락 깊이 조절
- 생성 후 열린 꺾임마다 "최고 속도로 바깥쪽을 계속 누르며 떨어지는" 경우를 실제 물리로 시뮬레이션해 착지 층을 잰다.
- 구간 최대 추락 층수보다 깊으면: 허용 깊이 안의 같은 쪽 아래 착지판 중 하나를 시드 난수로 골라 벽까지 늘려 받침으로 만든다(추락 깊이가 매번 달라지도록). 마땅한 착지판이 없거나 늘리면 규칙 위반이면 그 꺾임을 안전하게 바꾼다. 고친 뒤 다시 측정한다.
- 모든 발판은 경로의 일부. 바위 윗면에 떨어진 경우 양옆으로 걸어 내려가면 경로 발판에 착지하는지 검사한다.

### 60층 구간 (`config.zones`)

| 구간 | 디딤판 폭 | 비행 길이 | 열린 꺾임 확률 | 최대 추락 | 발판 모양 |
|---|---|---|---|---|---|
| 1~20층 | 2~3칸 | 3~4 | 0% | 0층 | 이끼 낀 나무판 |
| 21~40층 | 1~2칸 | 3~5 | 50% | 8층 | 이끼 돌벽돌 |
| 41~60층 | 1칸 | 4~7 | 75% | 30층 | 나뭇가지 |

- 60층: 벽까지 넓은 정상 발판 + 깃발. 발이 닿으면 완주.
- 시작: 바닥 왼쪽 끝에서 오른쪽을 보고 시작.

### 결정성
- 같은 시드 + 같은 config → 항상 같은 맵 (mulberry32 난수). 맵은 시작할 때 한 번 생성하고 플레이 중에는 바뀌지 않는다.

## 7. 그래픽

- 전부 코드로 그림: 문자열 픽셀 배열 → 오프스크린 캔버스. 외부 이미지 없음.
- **배경**: 나무 속 결·옹이·덩굴·빛줄기. 벽보다 느리게 움직이는 패럴랙스(0.5배). 높이에 따라 색 보간: 아래 짙은 따뜻한 갈색 → 중간 초록 → 꼭대기 금빛.
- **명도 대비**: 발판은 밝게, 배경은 어둡고 채도 낮게. 캐릭터는 진한 외곽선.
- **장식(충돌 없음)**: 풀, 꽃, 버섯, 매달린 덩굴, 반딧불·나뭇잎 입자.
- **캐릭터 '새싹이'** 16×24: 서기 2프레임, 걷기 4, 계단 톡 1, 떨어짐 2, 착지 1. 좌우 반전. (캐릭터 선택은 5차)
- **효과**: 착지 먼지, "−N층!" 글자, 큰 추락 시 화면 흔들림. 소리는 1차에 넣지 않음.

## 12. 1차-B 개편: "탭 한 번 = 한 칸" (2026-10-15 승인)

참고 영상: '무한의 계단'류 게임 — 버튼 한 번에 한 칸씩 빠르게 오르는 리듬, 큰 층수 숫자, 말풍선.
사용자 선택: ◀▶ 한 번에 한 칸 / 콤보 + 큰 층수 / 효과음 / 말풍선. 시간 게이지는 넣지 않음.

**이동**
- ◀ ▶를 누를 때마다 그 방향으로 한 칸. 누르고 있어도 반복하지 않음. 결과 (위에서부터 먼저 맞는 것):
  1. 그쪽 한 칸 위에 밟을 곳 + 머리 공간 → 오르기 (+1층, 콤보 +1)
  2. 같은 높이에 밟을 곳 → 옆으로 한 칸
  3. 몸 높이에 고체(바위·벽) → 부딪힘, 제자리 (콤보 끊김)
  4. 그 외 → 허공으로 뛰어 실제 물리로 추락 (콤보 끊김). 떨어지는 동안 조작 없음, 착지하면 칸 가운데로 정렬
- 한 칸 점프 0.09초(`step.hopTime`), 점프 중 누른 것은 최대 2개까지 기억(`step.queueMax`). 캐릭터는 항상 칸 가운데(x = 16·열 + 4)에 선다.
- 놓친 칸으로 뛰어나가는 속도 `step.missSpeed` 70px/s, 살짝 튀어오름 `step.missPopVy` 140px/s.

**맵** (계단 폭은 모두 1칸)

| 구간 | 비행 길이 | 낭떠러지 확률 | 잘못 눌렀을 때 최대 추락 |
|---|---|---|---|
| 1~20층 | 4~6 | 0 (꺾임은 바위가 막음) | 2층 |
| 21~40층 | 2~4 | 0.5 | 8층 |
| 41~60층 | 1~3 | 0.75 | 30층 |

- 비행 길이 1 허용 (지그재그). 안전한 꺾임은 바위 범퍼 우선(`rockBumperChance` 1).
- 검증: 봇은 탭 방식으로 정상까지. 모든 디딤판에서 좌우 '잘못 누르기'를 실제 물리로 시험해 구간 한도 이하인지 확인.

**게임 느낌**
- HUD: 화면 위 가운데 큰 층수(오를 때 톡 튐) + 그 아래 콤보, 오른쪽 위 시간·최고 층, 왼쪽 위 소리 버튼.
- 콤보: 오를 때 +1, 추락·부딪힘·1.5초 멈춤(`combo.timeout`)이면 0. 10·30·50마다 축하(소리·말풍선). 완주 화면에 최고 콤보.
- 효과음: WebAudio로 합성(파일 없음). 톡(콤보에 따라 음 높아짐, 최대 한 옥타브), 옆걸음, 쿵(부딪힘), 휘익(추락), 착지, 콤보 띠링, 완주 팡파르. 소리 끄기 상태는 기기에 기억(실패해도 동작).
- 말풍선: 출발·콤보·큰 추락 때 한마디, 최고 층이 10의 배수가 될 때 짧은 과학 상식(한 판에서 겹치지 않게).

## 13. 2차: 장애물 시험 구간 61~120층 (2026-10-15 승인)

사용자 피드백: 1~60층 난이도는 딱 적당. 위로 갈수록 인내의 숲 원숭이 바나나, 끈기의 숲 가시공 같은 장애물 + "타이밍 맞춰 쭉 올라가는" 느낌.
결정: 장애물 먼저 61~120층 시험 구간에서 손맛 확인 → 600층 확장(4차)은 다음. 500~600층은 그때 장애물을 겹쳐 최고 난이도로.
사용자 선택: 네 가지 모두(가시공·원숭이 바나나·무너지는 발판·도토리), 맞으면 튕겨나가 추락, 콤보 끊김 1.5초 유지.

| 층 | 장애물 | 동작 |
|---|---|---|
| 61~75 | 가시공 | 레일 위 3칸 구간을 좌우 왕복(1.6초). 그 층의 몸 높이만 위협 (아래층 대기 자리는 안전) |
| 76~90 | 원숭이 | 벽에 앉아 1.8초마다 그 층을 가로질러 바나나(100px/s). 던지기 0.3초 전 팔 들기 예고 |
| 91~105 | 무너지는 발판 | 계단 절반이 금 간 발판. 밟고 0.35초 뒤 부서짐(위에 있으면 추락), 3초 뒤 다시 생김 |
| 106~120 | 도토리 + 섞임 | 5칸 위에서 1.5초마다 떨어져 첫 발판에서 깨짐. 가시공·원숭이·금 간 발판도 드문드문 |

- 장애물 위치·움직임은 시드와 시간으로 정해짐(모든 학생 같은 패턴). 장애물 층끼리는 2층 이상 띄우고, 장애물 층 바로 아래(기다리는 자리)는 금 간 발판 금지.
- 맞으면: 맞은 방향으로 튕김(`obstacles.knockSpeed` 90, 튀어오름 180) → 실제 물리 추락, 콤보 끊김, 말풍선. 착지 후 0.6초 무적(깜빡임). 튕김 물리는 '잘못 누르기'와 같아 추락 깊이 검증이 그대로 적용.
- 공정성 검증: 장애물을 보고 틈을 기다리는 봇이 61~120층을 한 번도 안 맞고 올라가야 그 배치를 씀(아니면 장애물만 다시 배치).
- 계단: 61~120층은 2~4칸마다 꺾임, 낭떠러지 확률 0.5, 최대 추락 10층.

**구현 상태**: 2차 구현 완료 (2026-10-15, 자동 테스트 89개 통과). 기본 시드에서 가시공 4·원숭이 3·도토리 2·금 간 발판 13칸, 조심하는 봇 61→120층 7.3초 0회 피격, 서두르는 봇 9.5초 4회 피격 후 회복.

구현 중 정한 것:
- 가시공 레일은 계단을 한쪽 끝에 두고 **다음 계단 반대쪽**으로 뻗는다 → 한 번 왕복에 한 번만 지나가고, 빠져나가는 쪽엔 공이 없다.
- 원숭이는 계단에서 먼 쪽 벽 가지에 앉는다(반응할 시간). 앉을 자리(벽 옆 칸)가 막혀 있거나 그 층에 바위가 있으면 다른 층에.
- 튕겨 떨어지는 깊이·발판이 부서져 떨어지는 깊이도 그 구간 최대 추락 층수를 넘으면 그 자리엔 장애물을 두지 않는다.
- 공정성 봇은 2칸 앞까지 경로를 2px 여유로 예측하고, 서 있는 자리가 위험해지면 한 칸만 안전해도 피한다. 15초 동안 못 오르면 그 배치는 실패.
- 화면: 도토리가 떨어질 발판에 그림자가 점점 진해짐, 부서진 발판은 다시 생기기 0.6초 전부터 희미하게 보임, 맞은 뒤 무적 동안 깜빡임, 원숭이 던질 때 '휙' 소리(근처 8층 이내).
- 조정 패널: 장애물 슬라이더 7개(가시공 왕복·바나나 간격/속도·도토리 간격·부서지는 시간·튕김 속도·무적 시간), 61/76/91/106층 바로 가기. 슬라이더로 바꾼 값은 공정성 검사를 다시 하지 않으므로 마음에 들면 `config.js`에 넣고 새로고침해서 검증받기.

## 14. 최고 난이도 시험 501~600층 (2026-10-15 승인)

사용자 피드백: 61~120층은 "무난". 최고 난이도를 먼저 겪어 봐야 나머지(121~500층 곡선, 600층 길이)를 정할 수 있음.
보상 계획(5차): 완주하면 화면에 증명서 + 구글 시트에 완료 표시 → 선생님이 완주자 목록을 보고 보상. 전교 랭킹도 유지. → 완주는 조작하기 어려워야 함.
사용자 선택: 따로 시험(링크 대신 **시작 화면 버튼**), 어려움 요소 네 가지 모두, 추락 한도 없음(501층까지).

- `config.js`의 `hardTest`: 시드 20261060, 100층, `floorOffset` 500(화면 층 = 맵 층 + 500), 한 구간 — 1~2칸마다 꺾임, 낭떠러지 0.9, `maxFallFloors` 100,
  장애물 `spikeBall/monkey/acorn: [2, 3]`, `crumble: 0.7`, `double: 0.5`, `speed: 1.5`.

## 15. 돌풍 + 구간 연습 (2026-10-15 승인)

사용자가 새 장애물 추천(돌풍·반딧불 발판·이끼 발판·번개) 중 **돌풍**만 고름. "바람은 어려운 구간에서만" → 4차 600층에서는 위쪽 어려운 구간에만 넣는다.
- 규칙: `obstacles.gust` — 4초마다 예고(나뭇잎·'◀ 돌풍 ◀' 깜빡임·바람 소리) 0.7초 → 바람 1초. 방향은 왼쪽부터 번갈아. 맵 전체가 같은 시계.
- 바람이 부는 동안 0.35초(`hold`) 넘게 가만히 서 있으면 바람 쪽으로 한 칸: 옆 발판이면 옆걸음, 허공이면 잘못 누른 것과 같은 물리로 추락(→ 추락 깊이는 이미 구간 한도 검증됨), 벽·바위·위 계단이면 버팀.
  누르면(뛰면) 버티는 시간이 처음부터. 바람 속에 서 있으면 캐릭터가 기울고 밀리기 직전 떤다.
- 시험: 기본 맵 121~140층(`hazards: { gust: true }`, totalFloors 140) + 시작 화면 **구간 연습** 버튼(장애물 구간마다 자동 생성, 기본 맵에서만). 연습 완주는 "연습 완주! (기록 안 남음)".
- 공정성 검사에 돌풍을 넣음: 조심하는 봇이 바람에 한 번도 안 밀려야 함(돌풍만 있는 구간에서는 쉬지 않고 오르므로 0). 기다려야 하는 장애물과 섞을 때(4차)는 봇이 바람도 계산해야 함.
- 덤으로 고친 것: 정상 바로 아래 바위가 정상 발판을 막던 생성 문제(바위는 정상보다 3행 이상 아래에만).
